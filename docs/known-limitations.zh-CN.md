# 已知限制

[English](known-limitations.md) | **简体中文**

一份诚实的清单。这里的每一条要么是刻意划定的范围边界，要么是真实存在的约束，都不是疏漏，也没有
任何一条在运行时被更友好的措辞掩盖过去。

## 环境

* **没有做过实机验收。** 本仓库是在一台没有安装 QEMU 的宿主机上开发的。`palette doctor` 会
  如实报告这一点，`tests/e2e` 会跳过。所有关于 WHPX、真实采集延迟和客户机行为的说法都未经
  验证。
* **仅 Windows 与 WHPX。** KVM 路线在设计上已经留好位置——传输与进程保护接口都在——但没有实现。
  `NullProcessGuard` 会报告遗留进程保护不可用，而不是假装它可用。
* **不分发客户机镜像。** 基础镜像是运维侧的产物，需要记录来源与摘要。

## 能力

* **视觉模式不支持 Unicode 文本。** 严格键盘模式只覆盖 US 布局可打印 ASCII。中文、emoji 和
  多行文本需要客户机增强通道，而本构建只定义了它，并未实现它。
* **`type_text` 天生就慢。** 每个按键阶段一条输入消息，并且限速，所以 256 个字符就是数百次往返。
  它不与单击共用延迟预算。
* **一个服务进程一台 VM。** 管理器是按多台写的，但没有任何东西负责它们之间的调度。
* **仅垂直滚动。** 水平滚动在 QAPI 里可以表达，但是被刻意不暴露：它没有经过测试，“因为枚举里
  有所以就提供”是一种没有证据支撑的承诺。
* **无触摸、手势或压力输入。** 没有多点触控，没有相对指针锁定。
* **`vm_wait` 的变化与稳定判断是像素启发式。** 闪烁的光标、时钟或动画都能让两者失效。二者都不
  代表“应用已经空闲”。
* **没有剪贴板。** 宿主机的没有，默认情况下客户机的也没有。
* **没有音频、没有视频、没有 USB 直通、没有共享目录。**

## 正确性边界

* **像素比对无法发现语义变化。** 两张看起来完全一样的截图之间，按钮可能已经被挪走。付款、删除和
  提交仍然需要调用方自己的确认策略。
* **exactly-once 仅限进程内。** 去重是一个服务生命周期内的有界内存。跨崩溃时，诚实的回答是
  `unknown`，服务会这么说，而不是重放。
* **私有匿名管道无法被重新接管。** 如果服务进程死了，那台 QEMU 不可恢复；计划为 MVP 接受了
  这一点。
* **Frame 不做归档。** 每个 frame 只保留一张 64×64 缩略图，而且只是为了回答“画面变了没有”。
* **指针的真实位置未知。** 除非是服务自己移动的，`cursor_position_source` 就是 `not_observed`，
  它从不声称观察到了光标。
* **`screendump` 不是原子桌面快照。** 写出过程中发生的更新可能产生撕裂画面。它不会被呈现为一个
  事务性的视图。

## 运维

* **没有远程传输。** 只有 stdio。Streamable HTTP 需要 TLS、身份认证、按 VM 的授权、严格的
  `Origin`/`Host` 校验、限额与审计。
* **没有多租户隔离。** 一个运维、一个宿主用户。它能带来什么、不能带来什么，见威胁模型。
* **没有调度平台。** 一个客户端控制一台 VM；`vm_id` 的存在是为了能寻址多台，不是为了编排它们。
* **客户机增强工具默认关闭**且尚未实现。契约、权限开关和 mock 都在；传输层不在。

## 已经实现并测试的部分

免得上面这份清单被读成“什么都用不了”：MCP 工具面、QMP 客户端（分帧、id 关联、事件、超时、
断线）、带 PNG/PPM 回退的截屏、坐标换算、键码表与文本预校验、带 frame 隔离与请求去重的有界
单写入者动作事务、输入账本及其清理、overlay 创建与重置、路径收敛、审计流水、生命周期状态机、
客户机工具 bridge 及其权限开关，以及 `doctor` 报告——全部由不需要 hypervisor 的测试覆盖，
其中生命周期相关路径还跑在一个真实子进程上。
