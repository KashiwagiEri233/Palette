# 已知限制

[English](known-limitations.md) | **简体中文**

一份诚实的清单。这里的每一条要么是刻意划定的范围边界，要么是真实存在的约束，都不是疏漏，也没有
任何一条在运行时被更友好的措辞掩盖过去。

## 环境

* **本次变更没有执行扩展平台矩阵的实机验收。** Fake QMP 和子进程测试不能证明真实客户机启动、
  截图延迟或点击准确性。未配置真实 QEMU 与匹配镜像时 E2E 会跳过。
* **平台支持有明确范围。** 原生 Windows x86_64/WHPX、macOS Intel/Apple Silicon 的 HVF，
  Linux x86_64/aarch64 的 KVM 均有 profile 与进程保护。显式 `tcg-x86_64`/`tcg-aarch64`
  提供软件模拟，绝不自动回退。前提条件与尚未实机验证的矩阵见[平台指南](platforms.zh-CN.md)。
* **POSIX 内存限制是采样式的。** 每 250 ms 检查 RSS，允许短暂超调，并非 Windows Job Object
  等效硬上限。Supervisor 控制 QEMU 进程组，不能约束主动创建新会话逃离的程序。
* **不分发客户机镜像。** 基础镜像是运维侧的产物，需要记录来源与摘要。

## 能力

* **视觉模式不支持 Unicode 文本。** 严格键盘模式只覆盖 US 布局可打印 ASCII。中文、emoji 和
  多行文本需要客户机增强通道，而本构建只定义了它，并未实现它。
* **`type_text` 天生就慢。** 每个按键阶段一条输入消息，并且限速，所以 256 个字符就是数百次往返。
  它不与单击共用延迟预算。
* **没有跨 VM 调度。** 服务可以持有多台 VM，每台拥有独立动作队列，但不负责均衡资源或跨 VM
  调度工作。
* **仅垂直滚动。** 水平滚动在 QAPI 里可以表达，但是被刻意不暴露：它没有经过测试，“因为枚举里
  有所以就提供”是一种没有证据支撑的承诺。
* **无触摸、手势或压力输入。** 没有多点触控，没有相对指针锁定。
* **`vm_wait` 的变化与稳定判断是像素启发式。** 闪烁的光标、时钟或动画都能让两者失效。二者都不
  代表“应用已经空闲”。
* **没有剪贴板。** 宿主机的没有，默认情况下客户机的也没有。
* **没有音频、没有视频、没有 USB 直通、没有共享目录。**

## 正确性边界

* **`allow_agent_qemu_args` 一旦打开，服务所做的一切都不再成立。** 这不是一个待修的缺陷，而是
  这个开关本身的含义。见 `threat-model.zh-CN.md`。
* **像素比对无法发现语义变化。** 两张看起来完全一样的截图之间，按钮可能已经被挪走。付款、删除和
  提交仍然需要调用方自己的确认策略。
* **exactly-once 仅限进程内。** 去重是一个服务生命周期内的有界内存。跨崩溃时，诚实的回答是
  `unknown`，服务会这么说，而不是重放。
* **私有匿名管道无法被重新接管。** 服务退出后 Windows Job Object 或 POSIX supervisor 清理
  QEMU；新服务需要创建新实例。
* **Frame 不做归档。** 每个 frame 只保留一张 64×64 缩略图，而且只是为了回答“画面变了没有”。
* **指针的真实位置未知。** 除非是服务自己移动的，`cursor_position_source` 就是 `not_observed`，
  它从不声称观察到了光标。
* **`screendump` 不是原子桌面快照。** 写出过程中发生的更新可能产生撕裂画面。它不会被呈现为一个
  事务性的视图。

## 运维

* **没有远程 MCP 传输。** MCP 使用 stdio；带认证的本地运维 socket/pipe 仅供 CLI 使用。
  Streamable HTTP 需要 TLS、身份认证、按 VM 的授权、严格的
  `Origin`/`Host` 校验、限额与审计。
* **没有多租户隔离。** 一个运维、一个宿主用户。它能带来什么、不能带来什么，见威胁模型。
* **没有调度平台。** 客户端通过 `vm_id` 寻址 VM，跨 VM 任务协调仍由调用方负责。
* **客户机增强工具默认启用，但仍未实现。** 契约、权限开关、bridge 和 mock 都在；客户机内的
  服务及其传输层不在。启用该通道本身没有代价，也不会产生效果，直到有这样一个服务完成握手；
  因此 `vm_status` 把传输与服务分开报告，而对着没有服务的客户机的每一次调用都会以“不可用”失败。
* **受强制的出站白名单未实现。** `offline`、`restricted-lab` 和 `nat` 可用；`internet-allowlist`
  在启动时被拒绝，而不是用 user-mode NAT 近似实现——它不是白名单。
* **不处理 IPv6、DNS 重绑定与重定向。** `nat` 模式把宿主的出站能力原样交给客户机，包括宿主能解析
  和能到达的一切。

## 已经实现并测试的部分

免得上面这份清单被读成“什么都用不了”：MCP 工具面、QMP 客户端（分帧、id 关联、事件、超时、
断线）、带 PNG/PPM 回退的截屏、坐标换算、键码表与文本预校验、带 frame 隔离与请求去重的有界
单写入者动作事务、输入账本及其清理、overlay 创建与重置、路径收敛、审计流水、生命周期状态机、
客户机工具 bridge 及其权限开关，以及 `doctor` 报告——全部由不需要 hypervisor 的测试覆盖，
其中生命周期相关路径还跑在一个真实子进程上。
