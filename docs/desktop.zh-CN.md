# Palette Desktop 桌面应用指南

[English](desktop.md) | **简体中文**

**Palette Desktop** 是 Palette 的本地图形工作台（基于 Electron、React 19、TypeScript、Tailwind CSS v4 与 noVNC 构建），用于管理持久化的本机 QEMU 虚拟机，并与 MCP 视觉 Agent 客户端安全共用同一个后台进程（`RuntimeOwner`）。

通过桌面端，你可以：

* 导入只读 `qcow2`/`raw` 基础镜像或挂载系统安装 ISO 创建持久虚拟机；
* 在关机状态下图形化配置 CPU、内存、磁盘扩容、启动顺序、显卡分辨率、网络/端口转发与音频输出；
* 通过本机只读 RFB 画面网关连续查看客户机实时画面；
* 随时点击**接管**获取独占的人工键鼠控制权，或一键将虚拟机**恢复初始状态**。

## 1. 环境准备与从源码运行

### 桌面布局与会话

桌面采用全局导航、虚拟机与会话列表、对话区、虚拟机工作区四区布局。主页提供目标虚拟机选择和任务草稿入口；“虚拟机管理”保留创建向导、控制台、运行状态和硬件设置。设置包含运行环境、Agent、权限与审批、外观、快捷键和关于。

对话侧栏按虚拟机分组展示，不再单独列出“最近对话”。虚拟机管理列表与详情页使用全局图标导航右侧的完整内容区，不显示对话侧栏；返回主页或对话时恢复已保存的侧栏显隐状态与宽度。设置页使用独立的分类导航。

界面沿用项目原有组件样式：胶囊形操作按钮、圆角表单控件、较大圆角卡片和圆角菜单。同类控件在浅色与深色主题中保持一致。所有选择菜单跟随应用主题并支持键盘操作，画面缩放菜单在全屏中仍可使用；菜单展开时按 Escape 先关闭菜单，再按可退出全屏。

顶栏与最左侧图标导航使用相同底色。虚拟机列表、对话区和工作区共用四角完整圆角的连续内容表面，以细分隔线划分，各栏标题对齐。右侧与底部保留窄幅外层留白，让背景包裹内容区。关机画面直接显示启动入口；实时画面保留独立的缩放、全屏和人工控制操作。浅色与深色主题均采用此结构。

每个对话固定属于一台虚拟机，切换对话会切换右侧画面。支持新建、重命名、置顶、归档、删除、导出和搜索；任务草稿自动保存在本机应用数据目录，按配置目录隔离。保存失败会保留当前草稿并显示重试入口。归档对话可在搜索中找到。

内置 pi coding-agent SDK 在 Electron 主进程运行。在“设置 → Agent”中添加内置提供商并配置 API Key，或创建多个具名的自定义 OpenAI Chat Completions、Responses、Anthropic Messages 提供商。每个自定义提供商独立保存端点、加密密钥和模型列表，即使模型 ID 或端点相同也不会互相覆盖。支持图像输入的模型可以观察并操作对话绑定的虚拟机，纯文本模型支持聊天。启动视觉任务后，其截图会发送到所选模型服务。未配置时，主页继续保存任务草稿。

自定义提供商填写 Base URL 和密钥后，可点击“获取模型”，搜索并勾选需要的模型，也可手动添加。OpenAI 兼容地址通常包含 `/v1` 等 API 前缀；Anthropic 地址遵循 SDK 约定，通常不包含 `/v1`。获取模型使用新输入的密钥，或使用端点和 API 类型未改变时的已保存密钥；修改端点或 API 类型后需重新输入密钥以获取模型。获取操作只产生候选列表，保存提供商后才会持久化所选模型；重复导入会保留已有模型的名称和能力参数。不支持获取或获取失败时，表单和已有模型均会保留，可继续手动编辑。获取超时为 15 秒，模型数量上限为 1000。服务未返回能力信息时，默认关闭图像输入与推理支持，上下文为 128000 tokens、最大输出为 8192 tokens，可在模型的“高级设置”中调整后使用。

聊天选择器仅显示应用内已保存 API Key 且至少有一个模型的提供商；未配置的条目仍可在设置中编辑。“已配置”只表示保存了密钥，不代表已验证认证或模型调用；不使用环境变量凭据或账号登录。删除当前提供商、当前模型或移除其密钥后，会清空模型选择并禁用发送，需明确选择其他模型后继续，聊天记录和草稿会保留。任一任务运行或压缩期间禁止修改配置。旧版单一自定义端点会自动迁移一次，保留密钥、当前模型、effort 与工具调用次数；旧设置文件保留以便恢复。

聊天支持流式 Markdown 回复，可显示标题、列表、代码块、引用和表格，并保留停止、自动及手动上下文压缩。模型选择位于输入框右侧，显示当前模型与推理等级。点击后可打开按提供商分组的模型列表，搜索模型或提供商，并在“推理等级”中选择 effort；不支持推理的模型显示 Off 并禁用该选项。选择自动保存为全局 Agent 配置，运行或压缩期间不可修改；API Key 和自定义端点仍在“设置 → Agent”中配置。悬停或点击其左侧的上下文圆环，可查看估算 token 用量、剩余比例，并执行手动压缩。任务运行中、空对话及只读对话无法手动压缩；压缩后用量可能暂时未知，下一次模型回复后更新。对话区不再显示会话分支按钮。网页链接经校验后在系统浏览器打开；原始 HTML 和远程图片自动加载已禁用。切换页面不会停止任务；人工接管会先停止该虚拟机的内置任务。同一虚拟机只允许一个 Agent 运行任务驱动，其他客户端仍可观察。关闭应用会停止内置任务；选择后台运行时，后台和虚拟机继续运行。中断任务不会自动恢复执行。

API Key 通过操作系统安全存储加密；安全存储不可用时仅保留在当前进程内存中。对话以 pi JSONL 文件保存在按配置根隔离的应用数据目录。默认每次运行最多调用工具 100 次，可调整为 1–1000。内置 Agent 已直接接入可选中文输入、客户机剪贴板、QGA 二进制传输和 Windows 文件管理/PowerShell/进程/注册表/App/UIA/批量工具，按每台虚拟机的运行状态报告可用性，参阅[增强工具指南](guest-enhancements.zh-CN.md)。自动审批、步骤回放、OAuth 和第三方扩展安装尚未实现。

每个用户回合都有默认折叠的紧凑“执行过程”区域，收纳阶段说明、模型返回的思考及工具调用。展开工具行可查看参数、结果、错误及已记录的耗时。截图仅在展开对应工具行时加载，可点击放大，加载失败可重试；重新打开历史仍可查看，不会随每次流式更新重复传输。工具状态对应真实的参数准备、执行、完成、失败、停止或结果未知；结果未知时应先核对，再决定是否重复操作。

多步骤任务的系统提示词要求 Agent 在执行前调用 `todo_write`，在验证过的阶段切换时提交完整列表，并在最终回复前写入准确的最终状态；普通聊天中的清单不会更新面板，简单问答和单步任务可以省略计划。输入框上方默认折叠的面板显示最近一次成功写入的完整列表，可展开查看；状态包括待开始、进行中和已完成，最多一项进行中，受阻或未完成的任务必须保留未完成状态。历史工具记录保留每次列表及相对上次列表的变化。回合结束后保留面板，下一条用户消息开始时清空。它表示模型上报的进度，不是完成百分比或完成证明；模型是否遵循提示取决于所选模型。文本模型同样可以维护计划；更新计划不获取虚拟机控制权，也不消耗 VM 工具调用次数，其提示词会明确说明当前没有虚拟机观察和控制工具。

代码块显示语言、常用语言高亮及复制按钮，并反馈复制成功或失败；未知语言保留为普通代码。流式 Markdown 缓存稳定内容，生成结束后重新解析完整正文；暂不支持公式或任意本地文件链接。距底部不超过 80 像素时跟随输出，向上阅读时保留位置并显示“有新消息 ↓”。当前窗口内切换对话会保留滚动位置和展开状态。读屏仅播报阶段与终态摘要，不逐 token 播报；动画遵循减少动态效果设置。

最小窗口为 1100×700。侧栏在宽度小于1280时变成虚拟机图标列，工作区在有效宽度小于1100时使用抽屉。分隔条可拖动、双击恢复默认；布局与浅色/深色/跟随系统主题在本机保留。`Ctrl+N`新对话、`Ctrl+K`命令面板、`Ctrl+B`侧栏、`Ctrl+J`工作区；macOS使用对应的Cmd组合。人工控制可按`Ctrl+Alt`释放，也保留`Ctrl+Alt+G`；界面按钮显示“结束控制”。

完整目标见[GUI与内置 Agent设计规范](desktop-agent-design.zh-CN.md)，其中审批与回放接口仍为设计提案。

运行 Palette Desktop 需要：

* **Node.js**：`22.19` 或更新版本
* **Python 与包管理**：Python `3.12` 或 `3.13`，以及 [uv](https://docs.astral.sh/uv/)
* **QEMU**：安装匹配客户机架构的 `qemu-system-x86_64` 或 `qemu-system-aarch64` 以及 `qemu-img`

在仓库根目录安装依赖并启动开发模式：

```bash
uv sync --locked
npm --prefix desktop ci
npm --prefix desktop run dev
```

开发与生产构建会先使用固定源码和经校验的模型目录编译七个 vendored pi 包。正常构建不读取 `ref/`，也不在线获取最新模型目录。渲染进程不引用 SDK；模型请求在主进程运行，虚拟机工具通过后端 `hello` 返回的独立认证 Agent IPC 端点连接，使用 Unix socket 或 Windows named pipe。后台必须声明 `driver-claim-v1` 能力，使用视觉任务前需重启旧版后台。

执行类型检查、生产构建与本地预览：

```bash
npm --prefix desktop run build
npm --prefix desktop run preview
```

### 启动器与环境变量

* 当前版本不捆绑独立的 Python 或 QEMU 发行版；桌面端启动器始终从当前仓库通过 `uv` 执行 Python 后端模块。
* 在界面“环境设置”中切换配置目录时，该目录仅作为配置与运行目录（`palette.toml`、`profiles/`、`.runtime/`）来源。
* 若 `uv` 不在系统 `PATH` 中，可通过环境变量 `PALETTE_UV` 指定其绝对路径。
* 可通过环境变量 `PALETTE_ROOT` 指定桌面端启动时的初始配置根目录。

### 窗口与界面交互细节

* **一体化标题栏**：Windows 标题栏与工作区融合，保留系统原生最小化、最大化和关闭按钮；拖动顶部空白区或 Palette 品牌区即可移动窗口并支持系统窗口吸附，默认隐藏传统菜单栏。
* **自适应与独立滚动**：最小窗口尺寸为 `1100 × 700` 逻辑像素，遵循系统 DPI 缩放，中文界面优先使用微软雅黑。虚拟机设置面板采用内容区独立滚动，顶部标题与底部的保存/取消按钮始终固定可见；弹窗打开时系统窗口按钮区域随遮罩同步变暗，关闭最后一个弹窗后自动恢复。

## 2. 创建与管理持久虚拟机

### 创建虚拟机向导

所有创建入口使用四步向导：**选择配置 → 选择来源 → 配置虚拟机 → 确认创建**。

第一步选择 **预设** 或 **自定义**。预设提供 Windows、Linux，以及 x86_64 / ARM64 客户机架构；自定义保留可信 Profile 选择。系统预设独立于宿主运行配置，例如 Windows 宿主上的 Linux 客户机仍使用适合 Windows 宿主的加速方式。使用 TCG 时必须明确勾选软件模拟；没有匹配 Profile 的架构会显示不可用原因，不自动切换加速方式。

| 建议配置 | Windows | Linux |
| --- | --- | --- |
| CPU / 内存 / 磁盘 | 4 核 / 8 GiB / 80 GiB | 2 核 / 4 GiB / 32 GiB |
| x86_64 显示 / 网卡 | VirtIO VGA / e1000 | VirtIO VGA / VirtIO Net |
| ARM64 显示 / 网卡 | RAMFB / VirtIO Net | VirtIO GPU / VirtIO Net |

x86_64 预设优先使用 `virtio-vga`；所选 QEMU 缺少该设备时，Windows 使用 `VGA`，Linux 使用 `virtio-gpu-pci`，向导会显示回退原因。没有受支持候选的目标标记为不可用。ARM64 的 Windows 使用 `ramfb`，Linux 使用 `virtio-gpu-pci`。新默认值仅用于新建或主动重选预设；已有虚拟机及自定义 Profile 保留原配置。

网络模式、音频、存储控制器及固件沿用基础 Profile。在第三步可直接修改 CPU 核数、内存和磁盘大小，无需打开高级设置；创建按最终输入值保存。返回上一步或后台刷新保留编辑，更换配置前会确认是否覆盖已有修改。CPU、内存不得超过宿主总资源，磁盘容量不得小于导入镜像的虚拟容量；错误会在创建前提示。

预设代表用户选择的目标系统，不自动识别镜像内系统，也不安装驱动、配置 TPM 或绕过 Windows 安装检查。请自行准备匹配架构、固件和驱动的介质。Windows x64 增强工具与驱动安装 ISO 和菜单装载见[增强工具指南](guest-enhancements.zh-CN.md)。

第二步可选择两种来源：

1. **导入现有镜像（`qcow2` / `raw`）**：原始镜像始终作为**只读基础盘**使用（请勿移动或删除原路径及其 backing chain），Palette 会在 `.runtime/` 下为其创建独立的可写层。目标磁盘容量不能小于基础盘虚拟容量。
2. **从 ISO 安装系统**：自动创建指定容量的受管空白磁盘并挂载安装 ISO。固件（BIOS / UEFI）和磁盘驱动必须匹配目标客户机（例如 Windows ISO 安装可能需要挂载含 VirtIO 驱动的介质）。

持久虚拟机定义保存在 `<runtime_root>/definitions/` 下，受管可写磁盘与独立 UEFI 变量副本在关机、重启或创建新进程实例后均会持久保留。

> **与 CLI 临时虚拟机的区别**：直接通过 CLI 对未定义名称执行 `palette vm start` 时，仍沿用每次启动重建临时可写层的行为；而当 CLI 生命周期命令操作已在桌面端创建的持久虚拟机时，会自动遵循其持久磁盘与硬件定义。

### 生命周期与恢复初始状态

虚拟机管理列表每行直接提供**启动／关机**、**重启**、**暂停**、**虚拟机设置**和**删除虚拟机**。虚拟机处于活动状态时，启动按钮切换为关机。控制台、虚拟机列表和菜单中的电源／关机按钮在确认后强制停止虚拟机，相当于断电；确认框提示未保存数据丢失与客户机文件系统损坏风险，取消后虚拟机继续运行。安全关机请在客户机操作系统内执行，或从**更多**菜单选择**请求正常关机**。不可用的操作显示为禁用。暂停目前尚未支持，保留禁用入口。**更多**菜单保留强制停止与恢复初始状态，删除虚拟机仍需确认。

* **正常关机与强制停止**：电源键走独立的强制停止路径，不等待客户机关机请求。**请求正常关机**和**完全退出**使用正常关机路径：优先使用在线 QEMU Guest Agent 的关机能力；代理不可用或明确不支持时，通过 QMP 发送 ACPI 关机请求。代理请求结果未知时不会自动重发。暂停中的客户机先恢复运行，以处理关机请求。关机过程中控制台继续显示客户机画面，不显示遮罩；人工控制会释放，接管入口禁用。
  关机预算覆盖请求发送、代理锁等待与进程退出等待。超时或通道故障会显示错误；仍在运行的客户机不会被静默强杀。等待期间及失败后均提供**强制停止…**，必须另行确认；取消确认会继续原来的正常关机等待。强制停止可打断关机等待，无需等到超时；同时中止等待中的重启或恢复流程，避免随后创建新实例。
  确认仅针对原运行实例：若其他客户端已经重启虚拟机，Palette 会拒绝停止新的实例。强制停止可直接终止所属进程以打断被阻塞的关机；其他情况下先请求 QEMU 退出，必要时再终止进程及其守护范围。确认实际进程退出后才显示**已关机**；磁盘和 UEFI 变量保留。故障状态下仍存活的进程也可强制停止，不能作为已关机跳过。增强通道关闭与文件句柄清理均设有超时，避免关机被通道清理拖住。在客户机内部正常关机时，QEMU 发出客户机关机事件并成功退出后，Palette 会识别为**已关机**；崩溃仍显示为故障。
* **重启**：点击后直接执行硬件复位（`system_reset`），不弹确认，也不等待客户机正常关机。QEMU 进程、`instance_id`、持久磁盘与 UEFI 变量保留；未保存的内存内容会丢失。人工控制和 Agent 任务结束，旧画面及输入凭证失效，恢复画面后需重新接管。旧版后台需升级并重启后台后重新连接。
* **恢复初始状态**：丢弃受管理系统盘的可写层修改并重置 UEFI 变量——镜像来源回到原始只读基础盘状态，ISO 来源回到全新空白盘状态。附加磁盘和光盘镜像保留内容。
* **删除虚拟机**：仅清理 `.runtime/` 下受管理且无其他层依赖的文件，**绝不删除**用户导入的原始基础镜像或外部 ISO。

### 窗口关闭与退出行为

每次点击关闭窗口（即使当前没有任何虚拟机或全部已关机）都会弹出**“退出 Palette？”**确认框，提供两种模式：

* **仅关闭窗口**：关闭 Electron 界面，保留后台 `daemon` 和所有正在运行的虚拟机继续工作，MCP 客户端不受影响。
* **完全退出**：先向当前所连后台中的各台活动虚拟机独立发出正常关机请求并等待结果，再停止后台进程，确认后台进程彻底退出后关闭窗口（不会删除虚拟机定义或持久磁盘，也不会停止其他配置目录的后台）。若某台虚拟机正常关机超时或后台停止失败，窗口会保留并显示具体错误，允许重试、取消或改为“仅关闭窗口”。

若虚拟机操作尚未完成，**完全退出**会提示等待，不会排队重复发送关机请求，此时仍可取消或选择**仅关闭窗口**。关机失败后，即使退出弹窗仍然打开，也会刷新虚拟机状态；强制停止仍需单独确认。

**完全退出**过程中某台客户机关机超时或通道故障后，可点击**强制停止此虚拟机并退出…**，在单独的确认框中核对虚拟机名称与未保存数据丢失风险。确认后仅停止该实例，再继续正常关闭其他虚拟机并确认后台退出。取消确认会保留该虚拟机运行。此恢复流程要求后台已升级并声明 `vm-stop-identity` 能力。

ACPI 关机依赖客户机对电源按钮事件的处理，QEMU Guest Agent 依赖客户机服务；二者均不保证客户机一定完成关机。以 QEMU 进程实际退出为准，不能将黑屏作为已关机的依据。

## 3. 虚拟机硬件设置

Windows 下，中文目录或文件名的 ISO、磁盘及固件通过按系统代码页写入的 QEMU 介质配置加载，避免路径在命令行/JSON 与 Windows 文件 API 之间转换后失效。ISO 保持只读，磁盘格式仍显式指定。路径中的字符必须能由 Windows 系统代码页表示；无法表示时会在启动前明确报错。此兼容处理不代表运行目录及镜像 backing chain 已支持任意 Unicode 路径。

在虚拟机管理列表每行直接点击**“虚拟机设置”**，也可从虚拟机操作菜单或详情页进入，在以下六个分类面板中管理硬件配置。**运行中的虚拟机设置处于只读状态**，关机后修改并保存，于下次启动时生效。后台通过修订号（revision）校验防止并发会话互相覆盖，离开含未保存修改的表单时会提示保存、丢弃或继续编辑。

| 设置分类 | 支持范围与行为说明 |
| --- | --- |
| **常规** | 查看或修改虚拟机显示名称、备注说明与基础元数据 |
| **处理器与内存** | **vCPU**：`1–64` 核；**内存**：`256–1,048,576 MiB`。界面展示的宿主机物理核心与内存仅作参考，不代表资源预留 |
| **启动** | 可选择任意已连接介质的光驱作为启动光驱；启动顺序支持**自动**（首次启动优先光盘介质，后续优先硬盘）、**硬盘优先**与**光盘优先**（要求已挂载介质）。同类介质按侧栏顺序确定启动优先级 |
| **显示** | 根据客户机架构与本机 QEMU `-device help` 能力动态过滤可用显卡（如 `VGA`、`virtio-vga`、`virtio-gpu-pci`、`ramfb`）。支持为兼容显卡设置默认启动分辨率提示（`ramfb` 由固件或客户机决定，界面会说明限制） |
| **网络** | 支持 **离线（`offline`）**、**沙箱隔离（`restricted-lab`）** 与 **NAT（`nat`）** 三种模式；支持选择网卡型号、自定义 MAC 地址以及配置 TCP/UDP 端口转发。新增端口转发固定仅监听宿主机 `127.0.0.1` |
| **声音** | 通过 **Intel HDA** 将客户机音频输出到宿主机默认音频设备，**不采集麦克风**。要求 QEMU 具备对应宿主音频后端（macOS `CoreAudio`、Windows `DirectSound`、Linux `PipeWire`/`PulseAudio`/`ALSA`）且客户机已安装声卡驱动；缺少后端时会明确报错 |

虚拟机设置侧栏按**设备**和**驱动器**分组。每个驱动器独立列出，选择后编辑该设备；条目操作菜单可**上移、下移、删除驱动器…**。顺序、接口及其他编辑保存在同一份草稿中，切换条目和后台刷新不会丢失修改。

若连接的后台尚未加载新版驱动器管理代码，设置页会提示重启后台并重新连接，不会将缺失的能力信息误报为 QEMU 缺少存储接口。

创建虚拟机时生成的初始硬盘也是列表中的普通条目，可修改接口、访问方式、连接状态，也可排序和删除。删除在保存后生效，取消会保留数据。移除初始硬盘保留虚拟机及外部源镜像；再次启动或恢复初始状态不会重新创建已删除的硬盘。虚拟机可以不配置硬盘，直接通过光盘介质启动。

**新建…**先打开配置窗口，可选择**可移动介质**、**接口**，以及普通磁盘的**容量 / GiB**和**镜像格式（QCOW2 / RAW）**。普通磁盘点击**创建**添加空白磁盘，点击**导入…**选择已有镜像；可移动介质创建普通光驱，点击**浏览…**选择 ISO，也可直接创建空光驱。取消配置窗口或文件选择不新增设备。保存设置时才创建或导入文件。

磁盘接口包括 VirtIO、IDE、SCSI、NVMe、USB；光驱支持 IDE、SCSI、USB。界面根据本机 QEMU 设备清单及机器架构过滤实际选项：ARM64 不提供 PC 的 IDE 接口，VirtIO Block 和 NVMe 不作为光驱。客户机需要相应驱动，IDE 数量受机器端口限制。保存后的顺序用于设备构建及硬盘、光驱各组内的启动优先级；显式选择的启动光驱在光驱组内优先。

普通磁盘由 Palette 管理。导入会在虚拟机目录内生成指定格式的独立副本并展开 backing chain，保留原始文件；后续客户机写入仅修改副本。空白磁盘容量为 `1–4096 GiB`，导入使用源镜像的实际虚拟容量（不超过 `4096 GiB`）。详情显示名称、格式、虚拟容量和路径。已创建磁盘不可直接修改容量或格式；重启、恢复系统盘初始状态保留数据盘内容。

每个受管磁盘详情均提供**扩容磁盘**，包括初始硬盘及后续创建或导入的 RAW、QCOW2 磁盘。扩容是独立确认操作，需先保存或丢弃其他修改，仅支持增大，上限 `4096 GiB`。扩容保留外部源镜像和 UEFI 变量，不会自动扩展客户机内部的分区。中断后根据磁盘与操作记录恢复；无法确认完整性时阻止启动。

**删除驱动器…**确认后只从草稿移除，**保存**时才删除受管磁盘文件，**取消／丢弃修改**会保留设备和数据。外部 ISO 和此前接入的外部磁盘只移除设备，原文件保留。后台先校验其他虚拟机、镜像链和配置的引用，再提交配置并清理文件；清理失败保留待删除记录，可在**启动 → 未使用的磁盘**中重试删除并保存。未保存时不做删除，也不会因文件缺失自动新建空盘。

关机后最多配置 9 个驱动器，初始硬盘也计入总数；运行时只读查看。新接口选择及设备排序不改变已有设备 ID。新建与删除使用整个设置窗口的保存／取消，不再提供独立的立即删除文件操作。

安装 ISO 与其他 ISO 均为普通光驱介质，可在同一侧栏选择、更换、弹出或移除，不单独提供“安装介质”设置。断开磁盘、弹出 ISO、移除光驱均保留原文件。光盘优先需要至少一个已连接介质的光驱；最后一个可用介质弹出后，界面将启动顺序恢复为自动。暂不支持额外网卡。

> 创建虚拟机向导中的“更多硬件选项”复用显示、网络、音频和启动表单，附加驱动器在虚拟机设置中配置。旧版（v1）定义文件在读取时不改写磁盘，成功保存设置后自动升级格式；连接旧版后台时会提示升级而不会强制重启后台。

## 4. 实时控制台与人机控制权交接

### 只读画面网关（DisplayGateway）

未接管时，鼠标移入虚拟机画面仍显示本机指针；接管后使用客户机光标，结束控制后恢复本机指针。

打开“控制台”标签页时，默认处于**仅查看（View Only）**模式：

* 画面通过仅监听本机回环地址的 `DisplayGateway`（WebSocket RFB）连续传输，每次连接均使用由主进程申请的**一次性显示票据（one-time ticket）**。
* 网关在 RFB 协议层强制过滤所有客户端写入消息——即使前端修改了 noVNC 的只读标志，也无法通过显示通道注入任何键鼠输入。
* QEMU 管理凭据始终留在 Python 后台，运维 IPC 凭据留在 Electron 主进程，渲染进程保持沙箱隔离。Agent 的 `vm_observe` 截图仍走 QMP 通道，保持严格的帧坐标校验。

### 独占式人工接管（Human Control Lease）

1. 点击控制台工具栏的**“接管”**按钮，桌面端向后台申请该虚拟机的独占人工控制租约（`controller_epoch` 递增，Agent 手中所有旧 `frame_id` 立即作废）。
2. 再点击画面区域聚焦，即可进行实时点击、拖拽、滚轮、按键长按与组合键操作。工具栏提供一键发送 `Ctrl+Alt+Del` 与 `Super`（Windows/Command 键）。
3. 人工输入与 Agent 动作共用后台同一个单写入者控制器。人工接管期间，**Agent 仍可调用 `vm_observe` 查看画面，但任何 `vm_act` 写入请求都会收到 `BUSY` 拒绝**。
4. **物理按键说明**：人工按键按客户机物理键盘布局发送扫描码；当前版本不直接传输宿主机输入法（IME）合成文本或宿主机剪贴板。
5. **自动与手动释放**：按 **`Ctrl+Alt`**（也保留 **`Ctrl+Alt+G`**），或点击“结束控制”即可主动释放控制权。离开控制台页面、窗口失焦、最小化/隐藏窗口、退出全屏、客户机分辨率变化或连接断开时，均会自动释放键鼠并归还控制权；若前端心跳丢失超过 **3 秒**，后台租约会自动过期并释放所有按住的按键。

## 5. 共用后台与 MCP 协同

Palette Desktop、运维 CLI 与 MCP 客户端通过同一个 `runtime_root` 下的本地端点共用后台：

```bash
uv run palette daemon start           # 启动后台 daemon
uv run palette daemon status          # 查看当前 owner 信息与代次
uv run palette serve --connect-only   # 作为 MCP stdio 代理连接到已有 daemon
uv run palette daemon stop            # 停止后台并清理受管 QEMU 进程
```

* **自动发现与连接**：GUI 启动时优先连接已运行的兼容 owner；若不存在则自动在后台拉起 `palette daemon`。
* **`serve` 代理模式**：不带参数运行 `palette serve` 时，若发现已有兼容 owner 则自动作为轻量代理连接（MCP 会话断开不会停止 `daemon` 或虚拟机）；若当前没有 owner，则以 stdio 托管模式运行。若 GUI 连接到一个由 `serve`（stdio）托管的后台，界面会明确标注该模式。
* **状态实时同步**：GUI 的“状态”页每 **2 秒**轮询更新运行状态、当前 `instance_id`、控制权归属、`action_seq` 操作序号、排队任务数以及当前按住的键鼠状态。

## 6. 开发验证与测试

在提交代码或修改桌面端/后台交互后，运行完整验证套件：

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run python scripts/check_docs.py
npm --prefix desktop test
npm --prefix desktop run test:e2e
```

Electron Playwright 端到端测试（`npm --prefix desktop run test:e2e`）使用独立临时配置目录、受监督的 fake QEMU 子进程与真实的本机 WebSocket RFB 连接，自动验证创建虚拟机、修改硬件设置、控制台画面连接、人工接管与退出确认流程。实机客户机验收步骤详见[端到端验收测试指南](acceptance-test.zh-CN.md)。

可选的 VirtIO VGA 测试使用真实 x86_64 QEMU 启动一次性 BIOS 客户机。例如在 PowerShell 中运行：

```powershell
$env:PALETTE_VIRTIO_VGA_QEMU = 'C:/Program Files/qemu/qemu-system-x86_64.exe'
uv run pytest tests/e2e/test_virtio_vga.py
```

测试验证默认分辨率参数被接受、截图、认证 VNC、键盘和鼠标的显示设备绑定，以及键盘输入引起的实际画面变化。测试使用 TCG，并为最小 BIOS 客户机关闭 SMM；此结果不代表已完成 Windows/Linux 驱动或客户机桌面分辨率验收。

验证真实 QEMU 的多驱动器和工具光驱热添加时，将 `PALETTE_DRIVES_QEMU` 设置为同一可执行文件，再运行 `uv run pytest tests/e2e/test_real_drives.py`；同目录需有 `qemu-img` 和 `qemu-io`。测试检查读写磁盘、共享只读 backing 文件、装载和空载光驱、工具光驱新增/复用/弹出，以及其他介质保持不变，并通过离线写入、读取固定数据验证受管数据盘在重启和系统盘重置后保留内容。仅运行固件测试客户机，不验证 Windows 驱动安装。
