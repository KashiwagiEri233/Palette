# 性能基准与正确性指标（Benchmarks）

[English](benchmarks.md) | **简体中文**

在阅读或报告 Palette 的性能数据前，必须严格区分以下两条基本原则：

1. **目标预算 vs. 实测结果**：下表所列数值是架构设计的延迟预算（Targets），而非跨平台普适的实测承诺。实机单点验收耗时记录参见[端到端验收测试指南](acceptance-test.zh-CN.md)。
2. **测试替身（Mock/Fake）不等于实机性能**：仓库中的进程内 QMP 对端与受监督的 fake QEMU 子进程跳过了硬件虚拟化、客户机内核调度与图形桌面渲染，它们测出的毫秒级耗时仅反映 Python 服务层的序列化开销。**任何正式性能报告都必须明确标注每一行数据的运行模式（`mock`、`TCG`、`WHPX`、`HVF` 或 `KVM`）并记录宿主机与客户机架构**。

## 1. 如何在实机上运行测量

在配置好真实 QEMU 与客户机基础镜像的宿主机上，使用实机探针或 E2E 测试套件采集数据：

```bash
# 运行 P0 实机探针（输出冷启动、单次观察延迟与点击闭环耗时）
uv run python scripts/p0_probe.py

# 运行指定 Profile 的实机 E2E 验收套件
PALETTE_E2E=1 PALETTE_E2E_PROFILE=default uv run pytest tests/e2e -v
```

标准测量基线环境约定：单台虚拟机、分辨率 `1280 × 800`、`2` vCPU、`4 GiB` 内存、客户机内部无额外重负载；报告时需一并记录宿主机 CPU 型号、内存与磁盘类型。

## 2. 延迟预算目标（Targets）

| 测量指标 | 统计口径 | 目标预算 |
| --- | --- | --- |
| **`vm_observe` 端到端观察延迟** | 从发起请求到 MCP `ImageContent` 图像结果就绪（连续 100 次稳定采集） | **P95 ≤ 500 ms** |
| **`vm_act` 单击闭环延迟** | 从动作请求开始到动作后新截图就绪（普通鼠标单击，不含外部大模型推理耗时） | **P95 ≤ 1000 ms** |
| **实例冷启动耗时** | 拆分为三个独立阶段分别记录：`QMP 握手可达` / `首个有效显示缓冲区 (screen_ready)` / `桌面交互就绪` | **分阶段独立记录**（因客户机 OS 与加速器差异不设单一固定阈值） |

> **关于长文本输入的说明**：`type_text`（`mode: "keyboard"`）按字符逐个发送按键按下与释放事件，并受 `char_interval_ms`（默认 12 ms）限速保护，因此输入 256 个字符包含数百次 QMP 往返，拥有独立的超时预算（`max_total_ms = 15000`），不与鼠标单击共用 1 秒延迟目标。

## 3. 端到端耗时花在哪里

当某台宿主机上的实测耗时超出目标预算时，可按以下五个阶段逐一分解定位瓶颈：

1. **图像编码与缩放（Pillow PNG 编码）**：将原始帧缓冲转换为压缩 PNG 字节流往往占去最大比例的 CPU 时间（尤其在未缩放的高分辨率画面下）。
2. **截图临时文件 I/O**：QEMU `screendump` 先将帧缓冲写入 `.runtime/vms/<vm_id>/<instance_id>/frames/` 下的临时文件，随后由服务读取并立即删除。
3. **QMP 管道往返**：经私有匿名管道发送 JSON 指令并等待 QEMU 主循环返回响应。
4. **输入后画面稳定等待（`settle_after_input_ms`）**：输入事件提交后到触发动作后截图之间的配置等待窗口（默认 `120 ms`）。
5. **串行队列等待**：同一台虚拟机上排在前序未完成动作或截图请求之后的时间。

## 4. 物理正确性与稳定性标准

以下物理验收标准只能在真实 QEMU 与真实客户机镜像上验证，无法用替身测试替代：

* **全画布点击坐标精度**：在离线验收夹具（`guest/fixtures/offline-workbench.html`）的四角、中心及至少 200 个采样点上执行点击，落点误差 **≤ 原图 2 像素**。
* **分辨率动态变化防御**：会话中途改变客户机显示分辨率时，基于旧分辨率 frame 的动作必须被 `STALE_FRAME` 拒绝，绝不点偏到错误位置。
* **启停循环与镜像不可变性**：连续执行 **20 次**启动/停止/重置循环，宿主机无任何残留孤儿进程，且只读基础镜像的 SHA-256 摘要逐字节保持不变。
* **长稳压力测试**：在至少 **30 分钟**内连续执行 **1000 个**混合动作（移动、点击、拖拽、滚轮、按键、文本），验证零卡键、零句柄/内存泄漏以及 `.runtime/` 磁盘占用受控。
