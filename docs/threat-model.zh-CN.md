# 安全威胁模型（Threat Model）

[English](threat-model.md) | **简体中文**

本文明确定义 Palette 的信任假设、由 Profile 开关控制的边界、服务端强制执行的安全不变量，以及明确不在本系统防护范围内的事项。

## 1. 信任边界划分

### 永远视为不可信（Untrusted）

* **来自 Agent 或 MCP 客户端的一切输入**：工具参数、坐标、文本字符串、`request_id`、`frame_id`，以及任何关于自身权限或角色的声明。
* **客户机操作系统及其内部的全部程序**：包括可能被攻陷或试图攻击宿主机的客户机进程。
* **客户机屏幕上可见的一切内容**：网页、文档、弹窗、终端输出或图像中的文字。**屏幕内容永远只是数据，绝不是来自运维人员的指令**。
* **未来的任何远程网络客户端**。

### 视为可信（Trusted）

* **宿主机运维人员编写的配置**：`palette.toml` 与 `profiles/*.toml`、服务端权限策略与 Palette 自身代码。
* **宿主机环境**：运维人员安装的 QEMU 可执行文件、固件以及宿主操作系统内核与进程隔离机制。

## 2. 调用方材料开关：可被打开的宿主边界

Profile 的 `[lifecycle]` 部分包含三个宿主机材料开关。它们在 `profiles/strict-example.toml` 中**全部关闭**，而在随仓库提供的 `profiles/default.toml` 中为方便本地实验而**默认打开**。理解这三个开关（尤其是第三项）的安全后果至关重要：

| Profile 开关 | 开启后授予调用方的能力 | 开启后服务端仍能维持的边界 |
| --- | --- | --- |
| `allow_agent_images` | 允许调用方在 `vm_start` 时指定任意宿主机路径作为基础镜像，绕过 Profile 锁定的镜像路径与 SHA-256 摘要 | 实例可写层（`overlay.qcow2`）仍创建在 `.runtime/` 内并受重置与清理管控，但客户机运行的内容完全取决于调用方指定的镜像文件 |
| `allow_agent_iso` | 允许调用方从任意宿主机路径挂载一个或多个只读 CD-ROM（`iso`）或附加磁盘（`extra_disks`） | 外部文件以只读方式挂载并记录在实例 `manifest.json` 中（清理时永不删除外部文件），但客户机可读到被挂载的宿主文件内容 |
| `allow_agent_qemu_args` | 允许调用方追加原始 QEMU 命令行参数（`qemu_args`） | **无任何宿主边界保证。** `-chardev`、`-device`、`-blockdev` 可直接读写宿主机任意文件；`-mon`、`-vnc`、`-chardev socket` 可建立绕过 Palette 的第二条控制通道，使单写入者保证与所有参数级隔离全部退化为“仅作提示” |

> **为什么不对 `qemu_args` 做黑名单过滤？**
> 一旦允许调用方直接向 QEMU 传递命令行参数，试图维护一份“危险参数黑名单”只会制造虚假的安全感——QEMU 拥有庞大的设备与后端参数面，任何未被列入黑名单的别名或组合都能绕过过滤。因此 Palette 选择诚实地将其设计为一个独立的布尔开关：需要宿主边界时，将 `allow_agent_qemu_args = false` 关闭；打开它时，服务端仍会检测通过额外参数引入的 monitor 或显示通道并写入日志与启动回执，让边界变化保持可见而非静默发生。

## 3. 风险矩阵与服务端强制控制手段

在关闭 `allow_agent_qemu_args` 的标准安全姿态下，Palette 通过以下机制强制执行边界：

| 威胁与风险场景 | 服务端强制控制手段 |
| --- | --- |
| **Agent 试图通过管理接口控制宿主机** | 不提供 `qmp_execute`、不暴露 HMP、不提供通用 monitor 透传。QMP 客户端内置经过审查的命令白名单常量，任何未知 QMP 命令在发往管道前即在本地被拒绝 |
| **QMP 管理通道被外部进程窃听或注入** | QMP 在 POSIX 使用服务亲自创建的 QEMU 子进程私有标准输入输出，在 Windows 使用实例独立且目录 ACL 仅授权当前用户的 AF_UNIX 套接字；从不监听 TCP 端口，也不开启未受控的 VNC 或 SPICE 端口 |
| **实时画面连接被篡改用于注入键鼠输入** | Palette Desktop 使用的 `DisplayGateway` 仅绑定宿主机本地回环地址，采用一次性显示票据鉴权，并在 RFB 协议解析层直接丢弃一切客户端写入报文 |
| **路径穿越或误删宿主机文件** | 所有受管路径（`overlay.qcow2`、临时截图、日志、审计流水、持久定义）均由服务端根据可信配置与生成的随机标识拼接而成，并经 `PathGuard` 词法边界与符号链接/重解析点（junction/reparse point）双重校验严格限制在 `runtime_root` 内 |
| **客户机通过共享设备向宿主机渗透或泄密** | 默认不挂载 `9p`、`virtiofs`、SMB 共享目录，不开启宿主机双向剪贴板，不直通宿主 USB/PCI 设备，不采集宿主机麦克风，且子进程环境变量经过严格白名单清洗 |
| **客户机探测宿主机本地服务或内网** | `offline` 完全不附带网卡；`restricted-lab` 开启 QEMU user-mode `restrict=on` 沙箱，禁止客户机路由出沙箱；`internet-allowlist` 在启动时被明确拒绝而非用普通 NAT 冒充 |
| **QEMU 失控消耗宿主资源或沦为僵尸进程** | 动作耗时、文本长度、截图字节、队列深度与参数大小均有严格上限；Windows 使用 Kill-on-Close Job Object 硬限内存与生命周期，POSIX 使用独立 Supervisor 进程组与 250 ms RSS 采样 |
| **人与 Agent 或多个会话同时争抢桌面输入** | 每台 VM 仅有一个串行动作队列与单写入者控制器；人工在桌面端接管或执行 `take-control` 会立即递增 `controller_epoch` 并作废所有旧 `frame_id` |
| **审计日志意外泄露密码或敏感输入** | `audit/palette.jsonl` 仅记录动作类型、长度、耗时与结果错误码；**绝不记录**输入文本正文、启动参数、持久截图或宿主机文件路径 |
| **网页提示词注入（Prompt Injection）诱导提权** | 所有权限均源自宿主机静态 Profile，没有任何 MCP 工具能够修改权限策略或自行授予运维角色 |

## 4. 明确不在防护范围内的事项（Non-Goals）

* **已取得同一宿主机操作系统用户权限的恶意进程**：本地运维 IPC 使用当前用户受控的 Unix Socket（POSIX）或 Named Pipe（Windows）配合随机 Token。任何已能以同一宿主 OS 用户身份运行的进程都可以直接读取 `.runtime/` 或直接调用 QEMU 可执行文件。防御同用户进程需要独立的操作系统服务账户与容器/沙箱。
* **多租户隔离（Multi-Tenancy）**：单个 Palette 服务实例面向单一运维主体运行，不提供按租户划分的配额、权限或审计隔离。
* **高对抗恶意代码沙箱**：QEMU（尤其是未开启硬件虚拟化的 TCG 模式）提供的是操作环境隔离，而非经过形式化验证的零日恶意软件分析沙箱。
* **对视觉模型隐瞒屏幕内容**：截图的目的就是发送给 MCP 客户端所配置的视觉模型。不将截图落盘不等于模型没看过——请始终在客户机内使用测试账号与非敏感数据。
* **跨崩溃的严格恰好一次（Exactly-Once）执行**：`request_id` 幂等去重保存在当前服务进程的有界内存中。若在输入发出后、结果记录前发生进程崩溃或通道断开，服务会诚实返回 `effect_state = "unknown"` 或 `ACTION_OUTCOME_UNKNOWN`，**绝不自动重放**，由调用方先观察画面再决定后续动作。
* **MCP 工具注解不等于权限控制**：`readOnlyHint` 与 `destructiveHint` 仅供客户端 UI 展示提示，所有真实授权检查均在服务端强制完成。

## 5. 服务端给出的核心安全保证总结

1. **绝不跨实例或跨代次盲发输入**：任何坐标或文本输入都不会被发往 `instance_id`、`boot_epoch`、`controller_epoch`、`display_epoch` 或 `frame_id` 不匹配的实例。
2. **结果未知时绝不自动重放**：超时、连接中断或动作后截图失败一律如实报告状态，避免产生重复点击或重复提交。
3. **未验证的释放绝不谎报成功**：仅当底层通道确认释放完成时，`release_confirmed` 才为 `true`。
4. **只读基础镜像逐字节不可变**：`vm_reset` 与桌面端“恢复初始状态”均通过替换 `.runtime/` 下的可写 `overlay.qcow2` 与 UEFI 变量副本实现，外部基础镜像永不被写入或删除。
