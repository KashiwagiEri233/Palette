# 后端资源所有权与并发

[English](backend-architecture.md) | **简体中文**

Palette 通过统一应用层和共享运行时管理后端，保持 MCP、CLI、桌面 IPC 与配置契约兼容，无需数据迁移。

## 职责划分

| 组件 | 职责 |
| --- | --- |
| `AgentService` | 本地服务与远程 MCP 代理共同实现的类型化业务接口 |
| `PaletteService` / `LifecycleService` | 观察与动作编排；统一生命周期授权、实例身份校验与持久化 VM 路由 |
| `DesktopManager` | 运维侧 VM 创建、设置及持久化生命周期编排 |
| `DefinitionRepository` / `PersistentStorage` | VM 定义原子写入、磁盘所有权、扩容日志与恢复 |
| `VmManager` / `VmStorage` | 进程、QMP 会话、启动回滚、磁盘引用及保留策略 |
| `ActionController` / `ActionScheduler` | 动作事务与每实例唯一队列；帧授权、去重、事件规划及按键状态记录分别由独立组件负责 |
| `LocalListener` / `RequestRegistry` | 两类鉴权 IPC 协议共用的本机连接管理与有界操作所有权 |

## 并发操作

生命周期与定义修改按 VM 串行。重启和重置从停止、定义修改到再次启动始终持有同一次操作；同一 asyncio 任务内的嵌套步骤复用所有权。某台 VM 等待 QEMU 探测或关机时，其他 VM 仍可独立启停和修改设置。

控制权修改先获取 VM 操作锁，再获取该 VM 的控制权锁。输入统一通过实例队列执行，队列内部不反向获取生命周期锁。epoch 变化立即使旧帧与排队动作失效。各 VM 的租约到期处理独立推进。

共享磁盘引用更新与保留策略在运行时事件循环中作为同步事务执行。异步启动在探测 QEMU 前登记基础镜像、附加卷与持久化磁盘引用，防止尚未创建进程时被另一台 VM 的保留策略清理。成功、失败和取消都会释放临时引用。此协调不新增跨 VM 任务分配或宿主 CPU、内存总量准入限制。

## 关闭与故障

桌面正常关机通过 ACPI 请求执行，失败时报告错误而不强杀客户机。现有 CLI 关机回退与显式强制停止行为保留。授权和目标实例校验先于控制权修改，过期停机请求无法撤销新租约。

正常退出运行时会拒绝仍有进程存活、正在启动或排队启动的情况。完整关闭先禁止新启动，取消并等待在途启动及回滚，再关闭 IPC 和显示连接、释放控制权、停止 VM，最后释放运行时所有权锁。共享清理任务在调用方被重复取消后仍完成清理；独立步骤均会尝试执行，并保留首个错误。

IPC 去重仍为进程内有界机制。客户端断开不会取消运行时拥有的请求；已鉴权 Agent 请求发生参数冲突时返回现有结构化错误。输入结果未知或仅部分送达时，不会自动重放。

## 验证

并发测试通过事件屏障阻塞一台 VM，验证其他 VM 仍能推进。回归覆盖持久化重启/重置、启动取消、旧 backing layer 保护、过期停止请求、输入顺序及清理失败。fake QEMU 使用真实子进程和本地 IPC，但不代表硬件验收；显式配置的真实 QEMU 检查见[端到端验收指南](acceptance-test.zh-CN.md)。
